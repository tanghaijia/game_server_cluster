# 风险等级

`risk_level` 的作用不是代替 `can_start`，而是给调度系统一个**更细粒度的决策信号**。

`can_start` 只有两种结果：

```rust
true  // 可以启动
false // 不建议启动
```

但实际生产环境里，很多情况不是简单的“能 / 不能”，而是：

```text
可以启动，但资源比较紧张
可以启动，但只适合低优先级进程
不建议启动，但可以排队重试
严重不足，需要报警或迁移
```

所以 `risk_level` 用来表达**当前资源状态的风险程度**。

---

## 1. `can_start` 和 `risk_level` 的区别

例如：

```rust
pub struct PredictionResult {
    pub can_start: bool,
    pub risk_level: RiskLevel,
    pub reasons: Vec<String>,
}
```

含义可以这样理解：

| 字段           | 作用       |
| ------------ | -------- |
| `can_start`  | 最终是否建议启动 |
| `risk_level` | 当前资源风险等级 |
| `reasons`    | 为什么通过或拒绝 |

举例：

```text
can_start = true
risk_level = Low
```

表示资源充足，可以启动。

```text
can_start = true
risk_level = Medium
```

表示可以启动，但资源余量不多，建议谨慎。

```text
can_start = false
risk_level = High
```

表示当前不适合启动，建议稍后重试。

```text
can_start = false
risk_level = Critical
```

表示资源已经非常紧张，可能需要报警、扩容、迁移或清理进程。

---

## 2. 风险等级可以用于调度策略

比如你有不同类型的应用进程：

```text
高优先级服务
普通服务
批处理任务
后台异步任务
测试任务
```

可以按风险等级做不同策略：

| 风险等级       | 调度动作             |
| ---------- | ---------------- |
| `Low`      | 允许启动所有类型进程       |
| `Medium`   | 只允许启动高优先级或轻量进程   |
| `High`     | 拒绝普通进程，允许极少数强制任务 |
| `Critical` | 全部拒绝，并触发报警       |

比如：

```rust
match result.risk_level {
    RiskLevel::Low => {
        // 正常调度
    }
    RiskLevel::Medium => {
        // 只允许轻量任务或高优先级任务
    }
    RiskLevel::High => {
        // 暂缓启动，放入队列等待
    }
    RiskLevel::Critical => {
        // 拒绝启动，触发报警
    }
}
```

---

## 3. 风险等级可以用于重试和排队

如果只返回 `false`，调度器不知道应该多久后重试。

有了风险等级后，可以这样：

```text
Medium   -> 30 秒后重试
High     -> 2 分钟后重试
Critical -> 5 分钟后重试，并报警
```

示例：

```rust
fn retry_delay_seconds(risk_level: RiskLevel) -> u64 {
    match risk_level {
        RiskLevel::Low => 0,
        RiskLevel::Medium => 30,
        RiskLevel::High => 120,
        RiskLevel::Critical => 300,
    }
}
```

---

## 4. 风险等级可以用于日志和监控

例如你可以统计：

```text
最近 1 小时 Low 多少次
最近 1 小时 Medium 多少次
最近 1 小时 High 多少次
最近 1 小时 Critical 多少次
```

如果 `High` 和 `Critical` 次数持续增加，说明机器资源长期紧张。

可以用于：

```text
扩容判断
负载均衡
容量规划
报警
自动迁移
限流
```

---

## 5. 风险等级可以防止“贴线启动”

例如阈值是：

```text
CPU 阈值 = 80%
```

情况 A：

```text
预测启动后 CPU = 55%
can_start = true
risk_level = Low
```

情况 B：

```text
预测启动后 CPU = 79%
can_start = true
risk_level = Medium 或 High
```

这两种虽然都可以启动，但风险完全不同。

如果没有风险等级，调度器只能看到：

```text
true
true
```

这会丢失很多有价值的信息。

---

## 6. 推荐的风险等级定义

可以按资源余量定义：

```text
CPU 余量 = CPU 阈值 - 预测 CPU
内存余量 = 预测启动后的可用内存 - 保留内存
```

示例：

```text
Low:
  CPU 余量 >= 20%
  且内存余量 >= 2048MB

Medium:
  CPU 余量 >= 10%
  且内存余量 >= 1024MB

High:
  CPU 余量 >= 0
  且内存余量 >= 0

Critical:
  CPU 或内存已经超过安全边界
```

也可以简单写成：

```rust
fn classify_risk(
    projected_cpu_percent: f64,
    cpu_threshold_percent: f64,
    projected_memory_available_mb: f64,
    reserved_memory_mb: f64,
) -> RiskLevel {
    let cpu_headroom = cpu_threshold_percent - projected_cpu_percent;
    let memory_headroom = projected_memory_available_mb - reserved_memory_mb;

    if cpu_headroom < 0.0 || memory_headroom < 0.0 {
        return RiskLevel::Critical;
    }

    if cpu_headroom < 5.0 || memory_headroom < 512.0 {
        return RiskLevel::High;
    }

    if cpu_headroom < 15.0 || memory_headroom < 2048.0 {
        return RiskLevel::Medium;
    }

    RiskLevel::Low
}
```

---

## 7. 最终建议

保留 `risk_level`，因为它对后续扩展很有用。

你可以这样使用：

```text
can_start:
  用于当前这次是否允许启动

risk_level:
  用于调度策略、重试时间、报警、扩容、限流、任务优先级

reasons:
  用于日志、排查和解释决策
```

一句话总结：

> `can_start` 是最终决策，`risk_level` 是调度系统理解“有多危险”的上下文。
